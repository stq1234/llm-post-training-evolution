低资源合成证据问答中的大语言模型后训练：实现比较与实验分析


摘要


本文研究有限资源下监督微调、离线与在线偏好优化以及组相对策略优化如何影响模型的格式遵循、答案、证据和反事实行为。研究先对 TRL、trlx、DeepSpeed-Chat、OpenRLHF、verl、slime、open-r1 与 MiniMind 八种公开实现进行代码路径比较，再以 Qwen2.5-0.5B-Instruct 和 LoRA 在程序生成的中文短证据问答上开展实测，对照两种子 SFT-16、DPO、在线 DPO、完整奖励 GRPO 与格式奖励 GRPO；另将单种子 SFT-256 作为高预算监督对照。严格联合正确要求 JSON 合法、答案正确且证据集合精确匹配。三个测试划分的联合正确率（同分布、措辞留出、反事实）依次为：SFT 0.363、0.334、0.322；DPO 0.225、0.291、0.159；在线 DPO 0.366、0.366、0.378；完整奖励 GRPO 0.397、0.366、0.394。完整奖励 GRPO 相对格式奖励消融分别高 7.2、3.1、9.7 个百分点；DPO 在三个划分上的种子内配对差均低于 SFT。SFT-256 的单次得分为 0.994、0.831、0.706，不能作为等计算量或双种子比较。基线严格格式分数为零主要源于外层 Markdown 代码围栏；去围栏诊断显示其中仍有可解析且部分正确的答案。结果说明，在本合成任务和当前训练预算下，偏好目标的选择会同时改变格式、答案与证据行为，但两种子样本不足以支持显著性或广泛因果推断；词汇/措辞留出和反事实数据也不代表真实文档或开放领域推理。

1 引言


大语言模型的能力不只取决于预训练语料和参数规模，也受到后训练阶段所选监督信号、样本分布与优化目标的影响。指令微调以示范回答提高模型对任务指令的条件响应；人类反馈强化学习进一步把偏好判断转化为奖励，再用策略优化改变生成分布 [2–3]。直接偏好优化（DPO）将固定偏好对与参考策略概率比写入分类式目标，减少了奖励模型和在线策略更新链路 [9]；基于可验证奖励的强化学习则在数学、代码或格式约束等能够自动判分的任务上，将程序反馈直接用于策略更新 [10]。这几类方法并非只在算法形式上不同：它们对训练数据的来源、是否需要新生成样本、是否保存旧策略概率、参考策略扮演的角色，以及每条长短回答如何计入梯度，都有不同要求。


本文聚焦一个范围受控的中文证据问答任务，研究不同后训练信号怎样改变模型对格式、答案、证据和拒答的联合行为，并分析这些目标如何落实为训练张量、响应掩码、概率比和损失归约。实验以 Qwen2.5-0.5B-Instruct 为共同起点，采用低秩适配，在固定合成数据上比较监督微调、离线 DPO、在线 DPO、GRPO 及格式奖励消融。任务刻意将正确答案与支持证据分开计分，使仅猜中答案、遗漏必要证据或无据作答可以分别诊断。


研究围绕三个问题展开。第一，单一 gold 示范、静态合成偏好和当前策略采样后得到的程序奖励，分别提供何种训练信号？第二，组内相对策略优化在同一回答正确率、证据集合精确匹配率和拒答行为上的作用，是否会随 ID、词汇模板迁移及反事实事实变化而异？第三，公开后训练框架在概率缓存、token mask、损失归约、异步采样与恢复机制上的差异，如何影响目标的实际含义及小显存复现？


为回答这些问题，本文先对八种开源训练实现进行代码级比较，再将本地实验的目标函数逐一映射到数据字段和张量接口，最后给出合成任务、模型条件、训练配方和评测口径。框架比较用于解释可复现性与计算路径，不把各项目的算法名视为相同实现，也不将其他仓库的模型结果归属为本实验结果。实验范围限于小型合成证据问答，不评价预训练方法，不复现大规模人类偏好 RLHF，也不据此推断开放领域推理能力。

2.2 从策略目标到张量与计算图


监督微调把输入提示 x
i
 与示范完成序列配对，以自回归似然提高示范 token 的条件概率。本地实现对每条样本的有效目标 token 取平均负对数似然；T
i
 表示 completion 的长度并包括末尾 EOS：


$$
\mathcal{L}_{\mathrm{SFT}}^{(i)}(\theta)=-\frac{1}{T_i}\sum_{t=1}^{T_i}\log\pi_\theta(y_{i,t}\mid x_i,y_{i,<t}).
$$


实际 Trainer 会先把对话模板编码为 token ids，再构造 label mask。提示和 padding 标签设为忽略值，仅 completion 与 EOS 计入 T
i
。本地 SFT 的 micro-batch size 为 1，交叉熵在每个 micro-batch 内对有效目标 token 求均值；梯度累积时每个 micro-batch loss 再除以 4，因此一个更新步中的四条样本等权，而不是把四条回答的 token loss 总和除以全局有效 token 数。不同 Trainer 的归约方式可能不同；EOS 规则、截断处理和 padding 方向也会改变有效长度或梯度权重。


传统 PPO-RLHF 先由奖励模型对回答评分，再在策略更新目标中使用奖励与参考策略 KL 约束。其简化形式为


$$
\max_{\pi_\theta}\ \mathbb{E}_{x,\,y\sim\pi_\theta}[r_\phi(x,y)]-\beta\,\mathbb{E}_{x}\!\left[D_{\mathrm{KL}}\!\left(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid x)\right)\right].
$$


实践中的 actor 通常对一次 rollout 缓存响应 token 的 old-policy log-prob、value、mask 和 reward；广义优势估计（GAE）用折扣 TD 残差将稀疏终止奖励传播到响应 token：


$$
\delta_t=r_t+\gamma V(s_{t+1})-V(s_t),\qquad
\hat A_t=\sum_{\ell=0}^{T-t-1}(\gamma\lambda)^\ell\delta_{t+\ell}.
$$


PPO 再通过概率比裁剪限制单轮策略移动 [7–8]。可以将策略部分写成


$$
\mathcal{L}_{\mathrm{PPO}}=-\mathbb{E}_{t}\!\left[\min\!\left(\rho_t\hat A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right)\right],\quad
\rho_t=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\mathrm{old}}(a_t\mid s_t)}.
$$


对比之下，DPO 从二元偏好对（x，y
w
，y
l
）直接训练策略。它假设偏好概率服从 Bradley–Terry（BT）logistic 模型，并在 KL 正则化奖励最大化目标下，用最优策略与 reference 的概率比参数化奖励：


$$
P(y_w\succ y_l\mid x)=\sigma\!\left(r^*(x,y_w)-r^*(x,y_l)\right),\qquad
\pi_r(y\mid x)=\frac{1}{Z_r(x)}\pi_{\mathrm{ref}}(y\mid x)\exp\!\left(\frac{r(x,y)}{\beta}\right),\qquad
r(x,y)=\beta\log\frac{\pi_r(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}+\beta\log Z_r(x).
$$


将该奖励参数化代入 BT 偏好似然后，成对差分中的 Z
r
(x) 抵消，可直接对策略拟合偏好 logistic loss [9]：


$$
\mathcal{L}_{\mathrm{DPO}}=-\mathbb{E}\log\sigma\!\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\right]\right).
$$


因此 DPO 需要策略与 reference 对 chosen/rejected 响应计算序列似然，却不需要 PPO 语义下的 old policy、value head 或 rollout GAE。奖励分值可以用于筛选、构造 chosen/rejected，但它不是直接乘到 DPO 梯度上的策略优势。


GRPO 使用同一提示的一组回答作为局部比较集合，以组奖励均值和可选标准差归一化构造标量优势：


$$
\hat A_i=\frac{r_i-\mu_G}{\sigma_G+\varepsilon},\qquad
\mu_G=\frac{1}{G}\sum_{j=1}^{G}r_j.
$$


策略更新仍可采用 PPO 类 ratio clip，但它不含单独学习的 value critic。原始论文及后续配方可在 GRPO 目标中加入 reference KL；这并非所有 GRPO 变体的定义性条件，其他变体也可改变优势标准化、token/sequence ratio、损失分母和 off-policy correction [10, 12, 15–20]。本地实现明确包含一个采样 KL 项，其结论只适用于这里选定的目标。


公式只有映射到批次对象后才可复现。以一次策略优化为例，数据/rollout 先产生 prompt、completion 和样本身份；系统需保存或在更新前重算对应的 old-policy token 对数概率；奖励端对原始字符串按规则评分；组构造器按 prompt id 还原同组回答并计算优势；张量构造器记录完成 token mask；更新前重新计算当前策略 log-prob，与 old/reference log-prob 组合成 ratio、KL 和损失；最后按 batch 或 data-parallel 范围归约，再进行反向传播、裁剪和参数更新。本地 GRPO 采用“采样后以 policy 重新前向”构造旧策略锚点，并另行计算 frozen reference；在线 DPO 则不需 old-policy ratio。若任一环节丢失 prompt 组身份、误用参考概率替代行为策略概率、将 padding 纳入长度分母，或在异步权重版本间混合 rollout，得到的便不是同一个算法目标。


2.3 八种实现的调用链


2.3.1 TRL：Trainer 抽象下的历史 PPO、在线 DPO 与 GRPO


TRL 的版本演进展示了一个常用 Trainer 库如何从较直接的 PPO 经验循环转向具有多种损失、生成后端和掩码选项的策略训练器。v0.11.4 的 PPOTrainer 接收已编码 query、response 和 score；构造样本时计算行为策略、reference 策略与 critic 的响应 log-prob/value；KL 逐 token 写入非分数奖励，标量奖励放到最后一个有效 response token；GAE 产生优势后，训练 minibatch 更新 clipped actor 与 critic。这里 response mask 同时界定终止奖励位置、GAE 递推范围和两类损失的有效 token。[12]


当前 GRPOTrainer 则把 prompt 读取、completion 生成、多奖励函数评分、按 num_generations 分组和优势计算纳入生成批次路径。completion mask 可以与 tool mask 相乘，避免把工具执行文本自动视为策略动作；参考概率、old-training log-prob 与推理引擎采样 log-prob 可各自保留；若 vLLM 采样分布不同于训练模型，还能按 token 或整条响应进行重要性修正。GRPO、BNPO、DR-GRPO、DAPO、CISPO 等损失采用不同归一分母或截断形式，因此仅记录“使用 GRPOTrainer”不足以重建有效目标。[13]


TRL 在线 DPO 的调用链又与上述 policy-gradient 路径不同：对每个 prompt 采样两条回答，分别调用 reward function，按得分确定 chosen/rejected，再计算 policy/reference 的 response 序列 log-prob 和 DPO 损失。奖励用于排序，而非作为 token advantage；训练器不需要 critic 或 GAE。该设计降低了 PPO 模型角色数，却把生成与奖励调用引入每轮训练，并让偏好分布随当前策略变化。[13]


2.3.2 trlx：Accelerate 进程间的奖励分发


trlx 的 AcceleratePPOTrainer 将提示生成、奖励计算和 PPO 更新分成跨进程的数据路径。各进程生成响应后 gather prompt/completion，由主进程运行 reward function，再把 token-level scores pad 并 scatter 回各 rank；经验对象保存行为 log-prob、reference log-prob、value 与 score mask。参考 KL 写入 token reward，标量终止分数则定位于 EOS 一侧；计算阶段根据 old value 和奖励执行 GAE，再对掩码内有效 token 归一策略和值损失。训练器允许 PPO inner epochs、mini/micro-batches 及梯度累积。[14]


这一架构把 reward API 和分布式样本顺序变成训练契约：将奖励改成每个 rank 独立计算看似是吞吐优化，却必须保证 gather 顺序、返回分数和本地 experience 索引严格一致。其默认 token-level 归约也使长响应贡献更多有效动作项；若后续换为先逐样本平均再跨样本平均，样本长度相关权重即被改变。


2.3.3 DeepSpeed-Chat：阶段式 RLHF 与显式角色拆分


DeepSpeed-Chat 将后训练拆为指令微调、奖励模型训练和 PPO 强化学习阶段，同时提供独立 DPO 偏好路径。PPO actor 采样后，actor/reference/reward model/critic 分别前向；reference KL 作为逐动作 token 惩罚，RM 标量分数放到最后一个有效动作位置，value 与终止位置共同用于 GAE。Actor 与 critic 分步反向更新；混合精度溢出时配置可让双方同步跳过，避免一个角色前进而另一个停滞。生成经验先存入 MiniDataset，再按 PPO epochs 更新，之后保存 actor/critic 状态。[15]


其训练指南还把生成批量、PPO batch 与 generation_batches 的比例视作稳定性参数，并提示多轮复用数据时 old-policy 概率会与更新后策略迅速分离。DPO 分支使用 label mask 排除 prompt/padding，对 policy 和 frozen reference 分别计算 chosen/rejected 序列 log-prob，再执行偏好损失；因此 DPO 避开 critic/GAE，却仍需清楚记录静态偏好数据和参考 checkpoint。角色分离带来显存卸载、ZeRO 并行和独立服务配置的空间，也提高了模型状态同步与断点恢复的成本。[15]


2.3.4 OpenRLHF：角色编排、估计器选择与全局归约


OpenRLHF 通过 Ray ActorGroup 组织 actor、reference、reward 和 critic，并可将 vLLM 推理角色与训练角色共置。ExperienceMaker 对行为策略生成序列，分别计算 actor/reference 概率、reward 和 critic value，再保存 action log-probs、base/reference log-probs 及 mask；优势可选 GAE、RLOO、组内去均值/标准化等。PolicyLoss 也可采用 token PPO 或 GSPO 的 sequence ratio，并包含采样与训练策略失配时的 token/sequence correction。[16]


它暴露出两个往往被算法缩写遮蔽的选择。其一，优势估计器与 actor loss 类型是独立开关，称 GRPO 并不足以描述 ratio 和 clipping。其二，token-level loss 可按全局有效 token 数归一，sequence-level loss 则先平均每条响应 token 再按样本数归一；动态批处理下显式传递全局计数和 data-parallel 规模，避免 rank 上样本长度差异改变梯度尺度。生成—经验构造—训练—vLLM 权重同步—checkpoint 的阶段边界使高吞吐可扩展，同时增加奖励服务、角色组规划、权重广播与断点一致性的工程依赖。[16]


2.3.5 verl：队列数据流与 rollout/old/reference 三分


verl 当前 v1 流程从 Hydra 入口构造 TaskRunner、AgentLoopManager 和 Transfer Queue；每个训练 step 从 replay buffer 获取批次，按需计算奖励、平衡 DP 样本，再生成 old/reference log-prob、优势和值，更新 critic/actor。对带工具交互的 AgentLoop，响应字段在采样工作端形成，经 queue 传到训练端；于是样本键、字段语义和队列生命周期直接参与算法定义。[17]


策略概率可分为 rollout 服务真正采用的 π

、PPO 更新窗口固定的 π

。bypass 模式可将 rollout 概率作为 old；decoupled 模式另行计算 PPO anchor，重要性采样/rejection correction 则处理 rollout/训练差异。GRPO estimator 通过 uid 恢复 prompt 组，控制是否按标准差归一；组内单样本时以均值零、标准差一避免数值异常。其多种 aggregation（token mean、token sum、sequence/token mean 和固定 horizon 归一等）还需适配 FSDP 与 Megatron 反向尺度。若只保留策略权重而不保存 queue/replay buffer、数据加载器状态与 rollout 概率，恢复后的优化可以继续，但不等于逐样本重放同一训练轨迹。[17]


2.3.6 slime：异步 rollout 与可重放批次计划


slime 将 Ray/SGLang rollout 服务与 Megatron 训练后端分层：RolloutManager 生成或恢复轨迹，BatchBuilder 把原始响应、奖励和分段记录转为训练批次，再按数据并行切分交给 actor/critic。代码支持 PPO、GRPO、GSPO、CISPO 和 REINFORCE++ 等优势/损失路径，记录响应 token mask、行为 log-prob、KL、value、组别与权重版本；组奖励统计根据唯一 rollout id 计算，再映射到对话分段，而不是把 segment 误当作独立采样回答。[18]


其关键系统语义是异步样本与训练权重之间可能存在时间差。批次转换记录可保存样本选择、rollout id、分组标识及转换计划，崩溃后可重放原始采样结果；但“队列任务已完成”和“训练状态已与优化器、数据计划联合持久化”并非同一事件。大规模推理/训练重叠提升设备利用率，却要求保存采样权重版本、log-prob 来源、奖励结果、轨迹切分和队列状态，以界定 off-policy 校正与恢复语义。[18]


2.3.7 open-r1：任务奖励配方依托 TRL 内核


open-r1 将 problem 字段转换为对话提示，建立模型、数据集和 reward registry，再把奖励函数交给 GRPOTrainer。其配置锁定 TRL v0.18.0，因此组奖励、标准差、completion mask、参考 KL 和 GRPO/BNPO/DR-GRPO 分母都应按该版本实现解释，而非按后来 TRL 主分支倒推。accuracy reward 解析推理答案并与 gold 比较，format reward 检查指定标签结构，代码奖励可执行测试；训练配置中的权重、completion 长度、每 prompt 生成数和 vLLM 开关共同决定组奖励分布与采样成本。[19–20]


特别需要区分“不可评分”处理：该配方版本会将奖励函数返回的 None 转为 NaN 后沿奖励维求和；全函数均无数值时聚合为零并进入组统计。当前 TRL 主分支另有 unscorable mask 处理，不能将较新内核的行为归到固定依赖配方。open-r1 的研究价值在于展示任务数据、奖励和训练配置怎样接入通用优化器；它不是与 TRL 完全独立的 GRPO 实现，也不构成任何未公开闭源训练系统的代码证据。[19–20]


2.3.8 MiniMind：显式、可改造的单机训练回路


MiniMind 在单仓库提供 DPO、PPO 和 GRPO 训练脚本。DPO 数据集组织 chosen/rejected completion 与 response mask，分别前向 policy 和 frozen reference，累计响应 log-prob 后计算 reference-adjusted margin，并通过 AdamW、混合精度、梯度累积和 checkpoint 恢复完成更新。GRPO 由 rollout engine 统一 PyTorch 本地采样和 SGLang HTTP 接口，保留提示长度、每 token old log-prob 与完成 mask；奖励组合格式、长度/重复规则和奖励模型分数，之后按组均值及标准差计算优势，以 clipped ratio 和采样 KL 形成策略损失。[21]


该实现的 GRPO loss 先对每条回答的有效 token 求均值，再对样本平均，因此短答和长答的总损失权重较接近；它不等同于按整个批次 token 数归一，也不等同于以固定最大长度为分母的 DR-GRPO。训练完成保存时可同步 rollout engine 权重，并在 checkpoint 中保存优化器、调度器、step/epoch 状态。对于教学、小规模算法验证和本地改造，这种直线数据流易于检查；若 reference 整体权重双份常驻，则会挤占显存，需依实际模型、精度和设备测量。[21]


2.4 实现分歧如何改变复现实验


八个系统的差异集中在若干训练语义，而不仅是“单机还是分布式”。


首先，PPO 的旧策略和 DPO/GRPO 中的参考策略承担不同职责。DeepSpeed-Chat 在 rollout 后缓存 actor 的 old log-prob，并以 reference log-prob 构造 KL；OpenRLHF 的 Experience 分别保留 action 与 base 概率；verl 可将采样策略、PPO anchor 和当前策略分开；TRL 当前 GRPO 还可能保存训练旧策略与推理采样 log-prob。若使用后者的 rollout 概率直接充当前者，或将 reference KL 当作 PPO ratio 的分母，策略更新的校正对象就被混淆。异步服务更新权重时还要记录 weight version，确认训练批次实际由哪一组参数生成。[13, 15–18]


其次，损失的归一化分母决定回答长度怎样转化为样本权重。若将一个批次所有有效 token 的损失和除以全局 token 总数，较长回答通常贡献更多动作项；若先对每条回复 token 求平均、再对回复求平均，单条短答与长答的总权重更接近；固定 horizon 分母则把回答长度相对最大长度的比例也纳入尺度。trlx、OpenRLHF、verl、TRL 的 GRPO loss variants 和 MiniMind 采用不同约定。多卡或动态批次还涉及有效 token 总数是否跨 rank 求和，以及并行后端是否按 data-parallel size 再缩放。表 2 把这些差异转化为报告时应固定的比较维度。

这些工程实现不存在一条普遍取代其他实现的单线谱系：TRL 更接近可配置的 Trainer 与算法原型，open-r1 通过奖励和数据配方复用 Trainer 内核；trlx 和 DeepSpeed-Chat 展示了较直观的经验缓存与分阶段角色式 RLHF；OpenRLHF、verl 与 slime 将采样服务、角色调度、全局归约、异步队列和恢复数据纳入系统设计；MiniMind 保留紧凑的单机路径。框架间的选择取决于可用显存、采样吞吐、奖励服务、并行设备和复现粒度，不应将分布式架构复杂度本身理解为更好的算法，也不应以教学代码的简洁性推断其大规模吞吐。


2.5 本地训练目标到数据、张量与更新接口


本项目把理论对象映射为相同的输入模板和响应 token 区间。规则数据行包含 prompt、gold answer、evidence 与审计 metadata；训练器只把 prompt 和 target 送入 tokenizer，不将 latent fact graph 或标签元数据拼接到模型输入。chat template 添加 generation prompt 后，特征构造按同一 tokenizer 计算提示长度、padding 和响应掩码；prompt labels 设为忽略值，completion 与 EOS 构成有效目标区间。因此 SFT、偏好似然和策略梯度不会将提示词本身当成生成答案来训练。[11]


离线 DPO 的 batch 从 chosen/rejected 字段构造两条配对特征，分别求当前策略及固定 SFT reference 的响应序列 log-prob 总和，再计算概率比差和 logistic loss。在线 DPO 从当前 policy 生成同提示四条候选，先运行奖励检查；非并列时从最高分与最低分候选中采样成对回答，之后复用同一 DPO 概率比目标。GRPO 对每个 prompt id 分组候选，在同一模型完成采样后以无 dropout 的 policy 前向重算 old-token log-prob，再单独以 reference adapter 计算固定参考概率；奖励与响应 mask 一并保留，更新时重算 current log-prob，结合 clipped ratio 与采样 KL 项形成逐回答损失。该本地 GRPO 选用 reference KL 是配置选择；它不改变“组内相对奖励提供 critic-free baseline”这一结构，也不代表所有 GRPO 框架都有该项。[11]

3 任务定义与合成数据


3.1 任务输入、输出与答案证据约束


每个输入 x 是一段包含 4—6 条编号短材料及一个中文问题的提示；输出 y 必须是恰含 answer 和 evidence 两个键的 JSON 对象。answer 为非空字符串，evidence 为去重后的正整数材料编号数组。若材料不足以确定答案，答案须为“未知”，evidence 为空数组。评测把答案正确、引用全部必要证据、格式合法和联合正确分开计算，避免只看语义答案而忽略证据归因。


任务覆盖四种互补情形。lookup 需要从一条匹配事实中查找属性；two_hop 包含关系链连接或数值加和；unanswerable 的目标关系在材料中缺失，需要拒绝用常识补全；negation 则通过边界、唯一性与候选否定事实排除。negation 中候选名单只声明候选范围，不断言一定有人持有目标物；一条独立“仅一人保管”事实和两条候选否定事实共同确定唯一剩余候选，因此四条材料都属于最小支持集。


3.2 数据来源、划分与迁移条件


数据集由固定规则生成器构造虚构事实世界并渲染成短材料，不使用真实语料、外部检索结果或人工标注。生成器保留 metadata 中的潜在关系、实体、事实编号和查询，以便从输入事实重算标准答案和最小证据；这些审计字段不进入模型 prompt。偏好对由 gold JSON 和受控错误类型自动构造，不是人类偏好标签。表 3 汇总样本规模和用途。

3.3 奖励、偏好标签和指标的对应关系


完整任务奖励同时使用格式、答案和证据。设 I
format
 表示 JSON/schema 合法，I
answer
 表示答案字符串与 gold 相同，I
evidence exact
 表示证据集合与全部 gold 证据完全匹配，则


$$
R=0.10I_{\mathrm{format}}+0.45I_{\mathrm{answer}}+0.45I_{\mathrm{answer}\land\mathrm{evidence\_exact}}.
$$


格式合法但答案错误得 0.10；答案正确而证据不完全匹配得 0.55；答案和证据均正确且格式合法得 1.00。奖励不按部分 evidence F1 连续给分，以免多报材料获得中间奖励；F1 只作为评测诊断。JSON 空白和 key 顺序不影响格式判定，但代码围栏、对象外文本、重复键、额外字段、错误类型、重复证据编号和越界材料编号均使格式分为零。strict 训练奖励和主评测保持这一解析规则；另行报告宽松答案提取与“仅去除首尾代码围栏后重新 strict 解析”的诊断值，以区分内容正确性与外层格式包装。诊断分不替代或回写 strict format/answer/joint 主指标，也不进入训练奖励。

4 模型与本地训练方法


4.1 因果语言建模与 Qwen2.5-0.5B-Instruct


因果语言模型以从左到右的条件分布表示词元序列。对于任一 token 序列，


$$
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}),\qquad
\mathcal{L}_{\mathrm{pretrain}}(\theta)=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).
$$


因果掩码保证每个位置仅依赖先前和当前位置上下文。预训练学习一般语言分布，SFT 与偏好优化在既有分布上重排面向具体指令的条件响应；本实验比较的是后两类更新，不是预训练方法。实验基座为 Qwen/Qwen2.5-0.5B-Instruct。模型配置采用 24 层 decoder，隐藏宽度 896，SwiGLU 中间宽度 4864，词表大小 151,936，最大上下文 32,768，输入输出嵌入共享；配置和结构来源见技术报告及模型卡 [4–5]。


模型使用多头因果自注意力和分组查询注意力（GQA）。每层以投影得到 query、key 与 value；RoPE 对 query/key 施加位置旋转，因果注意力按未来位置掩码计算：


$$
\operatorname{Attn}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_h}}+M\right)V.
$$


该配置有 14 个 query heads 与 2 个 key/value heads，每头维度 d
h
=64，即平均每个 KV head 供 7 个 query heads 共享。预归一化残差块可写为


$$
\begin{aligned}
\widetilde H^{(\ell)}&=H^{(\ell-1)}+\operatorname{GQA}\bigl(\operatorname{RMSNorm}(H^{(\ell-1)})\bigr),\\
H^{(\ell)}&=\widetilde H^{(\ell)}+\operatorname{SwiGLUFFN}\bigl(\operatorname{RMSNorm}(\widetilde H^{(\ell)})\bigr).
\end{aligned}
$$


RMSNorm 用特征维均方根归一化并施加缩放参数。SwiGLU 使用 SiLU 对 gate 投影作门控，将结果与 up 投影逐元素相乘后经 down 投影：


$$
\operatorname{SwiGLU}(h)=W_{\mathrm{down}}\left(\operatorname{SiLU}(W_{\mathrm{gate}}h)\odot W_{\mathrm{up}}h\right).
$$


注意力子层在 token 间路由上下文，前馈子层对各位置独立施加非线性变换 [1, 4]。基础权重冻结，仅适配器参与训练；因此小规模实验测试的是既有指令模型上的低秩更新，不是重新学习上述解码器表征。


4.2 LoRA 适配与响应掩码


LoRA 将冻结权重 W₀ 与低秩增量 ΔW 相加：


$$
W=W_0+\Delta W,\qquad \Delta W=\frac{\alpha}{r}BA.
$$


其中 A 是 r × d
in
 矩阵，B 是 d
out
 × r 矩阵，且 r 远小于原始投影维度 [6]。实验设置 r=8、α=16，缩放系数 α/r=2；适配器仅接入每层 query/value 投影，dropout 为 0，不训练偏置。模型权重以 BF16 载入，使用 SDPA，训练关闭 KV cache 并启用 gradient checkpointing；这些选项降低本地显存占用，但推理采样仍生成完整候选序列。


训练输入经锁定 tokenizer 的 chat template 编码，提示加 generation prompt 不得超过 256 token。训练特征在批处理中采用右侧 padding，响应 mask 排除 padding 与 prompt；SFT label mask 只保留目标回答及 EOS。在线 rollout 每次为一个 prompt 生成候选；批量评测生成采用左侧 padding。DPO 对 chosen/rejected 两个响应各自求和序列 log-prob。GRPO 更新批次在内存中缓存 old 与 reference 的逐 token 对数概率，使更新比率和 KL 项仅在有效响应 token 上计算；持久 rollout 日志只保存对应的序列汇总值。响应上限 64 token，包括 EOS；如果生成到上限而没有 EOS，模型输出可被标记为截断，评测保留截断状态。


4.3 监督微调与离线 DPO


SFT 以每条 gold completion（含末尾 EOS）的 token-level 平均负对数似然训练 LoRA 参数；batch size 为 1，梯度累积 4 个 micro-batch loss，各样本等权。提示和 padding label 被忽略；优化器为 AdamW，weight decay 为 0，gradient norm clip 为 1.0。每个训练随机种子都以独立 LoRA 初始化在 512 行 SFT 池有放回抽样；主方法用 16 次 optimizer updates 建立 warmstart，再以对应 seed 的 SFT adapter 同时初始化 DPO/Online DPO/GRPO policy，并作为这些分支的固定 reference。另保留 seed 17 的 256 步 SFT 条件，用作高预算监督对照，不与双种子方法的均值混为一组。


DPO 针对同一 prompt 下 chosen 序列 y
w
 与 rejected 序列 y
l
 训练。其概率比 margin 为


$$
\Delta_\theta(x,y)=\log\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)},\qquad
\mathcal{L}_{\mathrm{DPO}}=-\mathbb{E}\log\sigma\!\left(\beta[\Delta_\theta(x,y_w)-\Delta_\theta(x,y_l)]\right).
$$


当前策略从对应训练 seed 的 16 步 SFT adapter 初始化；reference 是同一 seed、同一冻结基座上的该 SFT adapter 快照，不参与梯度。系数 β 控制 preference margin 相对 reference 的尺度。离线偏好对是预先构造的 256 对训练记录；每个 rejected 都对应明确错误类别，正确拒答不会被标为负例。DPO 计算回答 token log-prob 总和而非平均值，EOS 纳入序列概率、prompt/padding 不纳入。本实验离线与在线 DPO 的偏好标签或排序均由预定义程序规则给出，是 BT 建模的训练代理而非实测人类偏好；训练不使用验证或测试 prompt。


4.4 在线 DPO


本地“在线 DPO”指一种项目内实现，并非声称与某单一公开论文变体完全等同。对每个 seed，训练策略从对应的 16 步 SFT adapter 初始化，reference 取同一 SFT adapter 的冻结副本。训练时当前策略对偏好池 prompt 采样 G=4 个回答，temperature 为 1、top-p 为 1、top-k 为 0；完整奖励函数对每个候选作字符串格式、答案与证据评分。从最高奖励集合随机选 chosen、从最低奖励集合随机选 rejected，随后用固定 SFT reference 计算同一 DPO margin。奖励大小用于排序，DPO logistic loss 中并不直接乘以 reward 或 PPO advantage。组内所有回答奖励相同时，跳过该组而不更新参数；组仍消耗提示采样预算。每个更新步先完成本批提示的候选生成，再对可用偏好对重新前向计算 policy/reference 序列概率；DPO 目标不使用 PPO 式 old-policy ratio。rollout 记录保存 prompt、候选解码文本、评分、候选索引和截断标记，可用于文本级核对；它不保存生成 token IDs、逐 token 行为概率或逐批实际生成配置，不能据此精确重建 token 级采样轨迹。[11]


该方式保留离线 DPO 的 pairwise likelihood 目标，却让偏好对分布随当前 policy 更新。相较离线 DPO，它更能采集当前模型真正产生的错误类型，但生成和奖励开销增加，排序质量受离散规则奖励约束；相较 PPO/GRPO，它不需要 critic、GAE 和 old-policy ratio。由于 tie 跳过和生成长度不定，提示预算与有效 optimizer updates 必须分别报告。


4.5 GRPO 与格式奖励消融


对 prompt x
i
 生成 G=4 个 completion，评分 r
i
 后按本地组内总体标准差（unbiased=False）构造优势。回答在 64-token 上限前生成 EOS 时，EOS 纳入响应；达到上限而没有 EOS 时，生成器把其标为 truncated，但训练仍将完整生成前缀作为终止样本参与奖励评分、old/reference 概率计算和策略/KL 损失。该行为将“长度上限处终止”作为本次训练语义，不进行 bootstrap，也不排除截断样本；本实验按全部采样 completion 统计截断比例，并在结果中区分训练 rollout 与测试生成截断。[11]


$$
\hat A_i=\frac{r_i-\mu_G}{\sigma_G+\varepsilon},\qquad
\sigma_G=\sqrt{\frac{1}{G}\sum_{j=1}^{G}(r_j-\mu_G)^2},\qquad
\varepsilon=10^{-4}.
$$


对每个 token t，定义 rollout 与更新策略概率比


$$
\rho_{it}=\exp\!\left(\log\pi_\theta(o_{it}\mid x_i,o_{i,<t})-\log\pi_{\mathrm{old}}(o_{it}\mid x_i,o_{i,<t})\right).
$$


本地目标由逐 token PPO-style clipped surrogate 与 reference KL 估计构成，按回答有效长度平均，再对回答平均：


$$
\begin{aligned}
\mathcal{L}_{\mathrm{GRPO}}=&-\frac{1}{N}\sum_{i=1}^{N}\frac{1}{|o_i|}\sum_t m_{it}
\min\!\left(\rho_{it}\hat A_i,\operatorname{clip}(\rho_{it},1-\epsilon_c,1+\epsilon_c)\hat A_i\right)\\
&+\frac{\beta}{N}\sum_{i=1}^{N}\frac{1}{|o_i|}\sum_t m_{it}
\left[e^{\delta_{it}}-\delta_{it}-1\right],\\
\delta_{it}=&\log\pi_{\mathrm{ref}}(o_{it}\mid x_i,o_{i,<t})-\log\pi_\theta(o_{it}\mid x_i,o_{i,<t}).
\end{aligned}
$$


其中 m
it
 只选择完成 token 并包括 EOS，|o
i
| 是有效完成长度；ε
clip
=0.2，reference KL 系数 β=0.02。KL 项是本地所选训练目标的一部分，而非所有 GRPO 变体都必须保留的条件。old 和 reference log-prob 在 rollout 后以无梯度形式缓存；同批 prompt 组通过 update_epochs=2 复用两次，再重新采样。组内奖励相同时优势为零，此时策略代理项为零，但所选 KL 项仍可有梯度。它与在线 DPO 的 tie 规则形成有意的目标差异。


格式奖励消融在同一 GRPO 数据流和生成预算下，仅使用 JSON/schema 格式指示量，不读取 gold answer、证据集合或当前行材料边界。完整奖励 GRPO 与格式消融因此比较的是监督信息，而不是单纯优化器替换：前者可从答案和证据正确性接收反馈，后者只可优化 JSON/schema。若格式指标提升但 joint correct 不变，解释应聚焦可解析格式而非任务能力；若两者共同变化，还须结合生成长度、奖励分布与拒答结果分析。

5.2 公平性、选择与硬件记录


所有方法使用相同基础模型、tokenizer、对话模板、LoRA rank/alpha 和目标投影层；LoRA 参数为 r=8、α=16，仅 q/v 投影，BF16，dropout 0，AdamW、权重衰减 0、梯度范数裁剪 1.0。训练 micro-batch 为 1；在线 DPO 与 GRPO 通过梯度累积 2 合并两个 prompt 组，SFT warmstart、高预算 SFT 控制与离线 DPO 梯度累积 4。提示上限 256 token、生成/目标响应上限 64 token。各学习率与预算按表 5 固定；并不通过修改更新轮数来强行对齐生成、反向计算或墙钟时间。


validation 的 96 行与训练/测试提示分离，用于选择主实验 SFT warmstart。预先规定先筛选格式正确率不低于 95%、同时严格 joint_correct 低于 95% 的候选，再取更新步数最少者；16 步和 32 步候选均满足条件，validation format/joint 分别为 98.96%/43.75% 与 100%/76.04%，故选择 16 步作为两种子主实验共同的起点。seed 17 的 SFT-256 validation format/joint 为 100%/97.92%，作为充分监督高预算对照保留，不替代双种子 warmstart。该模型选择只使用 validation，不使用测试集。训练循环本身不在每步自动跑 validation，也不基于 validation 指标保存 best checkpoint；这些得分来自独立的 checkpoint 评估，而不是自动早停或 best-model selection。test-ID、test-OOD 与 test-counterfactual 只在模型条件确定后进行最终测量。


实验在 6 GiB（6144 MiB）NVIDIA RTX 3060 Laptop 上运行。资源统计包括阶段耗时、生成与更新 token 数及峰值 allocated memory；在线方法另报告 prompt rollout 数、候选数、实际更新数、并列组数和截断率。生成上限为 64 token 且未产生 EOS 的 completion 标记为 truncated；在线 DPO 与 GRPO 的此类前缀仍进入奖励评分，若被 DPO 极值对选中则参与 pair loss，GRPO 则参与优势和响应 token 更新。本次训练 rollout 与测试生成均按全部候选统计截断比例，并将此类输出视作长度上限处的终止样本。[11]


5.3 评测与统计


最终评测对 ID、OOD 和反事实数据均用贪心解码，beam 数为 1，temperature 采样关闭，最大生成长度 64 token；批量 8。评价器逐行保存 prompt、预测文本、任务类别、生成长度、截断标记与各项打分，并汇总 format_valid、answer_correct、evidence_exact、evidence_f1 和 joint_correct。宽松答案正确率与去除外层围栏后的联合正确率作为格式诊断计算，不参与优化和主指标定义。基线的严格分数与两项诊断分开呈现，以区分 JSON 外层格式问题和答案内容。测试结果按四类任务分层，分母均为每类 40 条；总体 accuracy 不替代证据集合精确匹配率或不可回答题表现。


abstain_correct 只对不可回答样本定义，其条件为答案为“未知”且证据集合为空；这一条件与该任务类别的 joint_correct 完全一致，结果按不可回答子集的联合正确率报告。evidence_f1 衡量部分证据重叠，作为证据集合精确匹配之外的诊断量；主要联合指标仍要求答案与全部必要证据同时正确。


反事实结果按 80 对而不是 160 个独立样本汇总。pair-complete accuracy 仅在同一对的两个成员都达到严格 joint_correct 时计为成功，用于衡量事实改变前后的联合回答是否同时正确；另按严格答案抽取规则统计两侧预测答案变化率，以及两侧答案分别匹配各自 gold 的正确变化率。答案变化诊断以全部 80 对为分母，无法解析或格式不合格的预测按失败计；预测变化不要求正确，也不要求证据正确。


主实验双种子条件逐 seed 计算，再报告均值及种子最小—最大范围；seed 17 的 SFT-256 高预算控制单独呈现，不并入双种子均值。样本数是各测试划分的固定记录数，同一方法的模型输出在同一提示上配对。两个种子只能展示有限的运行波动，不能支持统计显著性或高精度总体方差结论。正文案例覆盖 JSON/schema 无效、不可回答题猜答、答案错误，以及答案正确但证据不精确；按预定的每方法/类别最多一例规则选取，仅用于展示错误类型，不代表发生频率。


5.4 预设的可比性边界


四类训练目标使用的监督信息、候选生成成本和样本数不同。SFT 学习 gold 序列；离线 DPO 学习预设规则偏好；在线 DPO 学习当前策略样本经 reward 排序后的极值偏好；GRPO 使用同组 reward 差值形成每条回答的策略优势；格式奖励 GRPO 只学习可解析结构。分数差异因而同时包含优化目标、训练轨迹和监督信号变化，不能单独归因于优化器缩写。


评测集为小规模程序生成数据，ID 与 OOD 在任务逻辑上相同，OOD 主要操纵词汇与模板，反事实测试是有限的一事实改变。评测支持对所定义短上下文任务的比较，不足以证明真实资料上的证据识别、开放世界拒答校准、长程 agent 能力或大规模 RL scaling。资源比较还须结合峰值显存、采样 token、更新次数和耗时；本地 6 GiB 条件只代表这条硬件路径，不说明其他型号上的普遍训练能力。

7 讨论


7.1 监督量、输出格式与证据约束


SFT-16 主要提升了 JSON 格式，但其同分布联合正确率仍只有 0.363；答案和证据两个子指标的差异说明，形式稳定与基于材料的证据归因不是同一能力。SFT-256 单次运行在各项测试明显高于短 warmstart，和增加 gold 示范更新后对本任务的适配相一致。由于该控制只有 seed 17，训练次数是 SFT-16 的 16 倍且运行时间更长，它只能作为高预算监督对照，不能与双种子偏好方法视作等计算量的算法比较。


两步关系/加法任务仍是主要短板。除单种子 SFT-256 外，主方法的同分布任务联合正确率均不高于 0.100；在线 DPO、完整 GRPO 分别为 0.037 和 0.013。相较之下，在线 DPO 与完整奖励 GRPO 在不可回答任务都达到 1.000。该模式说明规则奖励在拒答和直接可验证约束上的反馈较明确，但并未在当前短上下文设置中转化为稳定的多步关系组合或算术能力。由于测试每类只有 40 条、两个种子范围很有限，细微差异不应过度解释。


7.2 偏好优化的经验结果及机制线索


静态 DPO 使用 256 对由规则构造的 chosen/rejected 数据并从 SFT-16 初始化。它在三个划分上都低于同 seed SFT，尤其在反事实测试中 joint 仅为 0.159、双题成对成功率仅为 0.044。SFT reference 提供了明确的相对概率锚点，但 reference 并不纠正偏好标签或 rejected 构造本身的覆盖问题。错误案例中的不可回答猜答和证据过度列举与这一观察一致，不能据单例推断错误的频率或唯一机制。


训练日志显示 DPO 偏好 margin 大幅上升，同时 rejected 相对参考 log-prob 下降远大于 chosen 项的下降。该变化表明训练确实强化了训练偏好对的区分，但不提供测试分布上的正则化证据；测试退化也可能涉及数据分布、奖励标签构造、序列求和目标和有限训练预算。若要分离这些解释，需要对拒答负例、证据错误类型和目标归一化分别控制，而当前结果不支持因果归因。


在线 DPO 与 GRPO 让当前策略样本接受程序评分，改善了整体测试联合正确率和反事实双题成功率，但它们使用不同采样与更新路径。在线 DPO 的并列组跳过令其实际更新为 52 步；GRPO 每个 rollout 批次复用两次更新，并在全奖励并列组仍保留 KL 梯度。格式消融的并列组占多数，使大量组内策略优势为零；full reward 则能利用答案与证据奖励产生更多非并列组。这为完整奖励相对格式奖励的优势提供了与机制相符的解释，但奖励信号与样本组差异并非单独操纵，因此不等于对每个奖励分项的因果实验。


7.3 目标实现与系统比较的含义


八种公开实现的代码路径说明，算法名不足以确定概率缓存、组构造、损失分母或训练恢复语义。本地实现将这些对象具体化为右侧训练 padding、响应 label mask、DPO 的策略/reference 序列概率和 GRPO 的逐响应 token 概率与长度均值。SFT 按每条 completion 的 token 平均损失并等权累积样本；DPO 则对序列 log-prob 求和；GRPO 对每条 completion 的有效 token 先取平均再对 completion 平均。这些归约在回答长度变化时赋予不同权重，是方法比较中应明确的条件。


本文的代码审查用于说明公开框架中的接口与实现分歧，本地实验则是一个小型、可检查的参考路径，不复现任何八个框架的分布式调度、异步 rollout 或大规模策略更新。运行日志对 GRPO 只保留序列汇总 log-prob 和解码文本，无法逐 token 重放采样轨迹；可据此分析目标、奖励与更新统计，但不能据此验证采样随机过程的逐 token 复现。


7.4 局限


评测数据是程序生成的虚构中文短证据任务，ID/OOD 每个划分各 160 条；OOD 主要改变词汇与措辞模板，反事实仅作一事实替换。它没有真实文档噪声、长上下文检索、外部工具或人工偏好标注。实验只使用 0.5B 指令模型和 LoRA，不代表全参数训练、较大模型或更广泛任务中的方法排序。偏好及奖励依赖固定规则，在线反馈不能代表用户偏好；DPO 与 GRPO 也存在预算、采样和更新复用差异。主方法仅两种子，SFT-256 与基线均为单次运行；本地耗时包含共享图形负载。上述条件限定了结果的外推范围。


8 结论


在本次合成短证据问答实验中，严格联合评分揭示仅提升格式不等于答案与证据同时正确。两种子 SFT-16 建立了稳定 JSON 输出，但多步关系/加法与反事实成对成功仍有限；离线 DPO 在三个测试划分均低于同 seed SFT，且偏好 margin 轨迹只能提供训练机制线索。在线 DPO 和完整奖励 GRPO 在该任务上取得较高的联合正确率，完整奖励 GRPO 也优于只奖励格式的消融；但它们的 rollout 成本、并列组和更新轨迹并不等价，且两种子不足以支持显著性或普遍优越性结论。


对本实验问题的回答因此受数据与目标边界约束：监督、成对偏好和当前策略程序奖励会改变可解析格式、答案选择和证据集合的相对表现；正确格式、正确答案、完整证据与随事实更新仍需分别衡量。八个源码实现对采样概率、损失归约及更新接口的差异，也说明可复现比较必须报告具体数据流和张量目标，不能只列算法名称。下一步需在更丰富的非合成资料、更多独立运行和受控奖励消融中验证这些观察。
